## 一、架构总览

### 1.1 技术选型

| 层次 | 技术 | 说明 |
|------|------|------|
| 框架 | Spring Boot 3.x | 单体应用基础框架 |
| AI 集成 | Spring AI Alibaba | 统一接入阿里百炼/通义千问 |
| LLM | 通义千问 qwen-max / qwen-plus | 通过 DashScope 自动配置 |
| Embedding | DashScopeEmbeddingModel（text-embedding-v2） | 1536 维文本向量化 |
| 向量存储 | **Elasticsearch 8.x** | 向量语义检索 + BM25 关键词检索 + 混合检索 |
| ORM | Spring Data JPA / MyBatis-Plus | 数据库访问 |
| 数据库 | MySQL 8.0 | 业务数据存储 |
| 缓存 | **Redis 7.x** | 热点知识缓存、会话状态、限流计数、JWT 黑名单 |
| 安全 | Spring Security + JWT | 认证与授权 |
| API 文档 | SpringDoc OpenAPI | 自动生成接口文档 |
| 定时任务 | Spring Scheduling | 知识库同步等 |
| 前端 | Vue 3 + Vite（独立部署或静态资源） | SPA 前后端分离 |

> **向量存储选型依据**：在单体应用中，向量存储有 4 个候选方案：

| 方案 | 优势 | 劣势 | 结论 |
|------|------|------|------|
| **Elasticsearch 8.x** | ✅ 原生支持 dense_vector + BM25 稀疏检索<br>✅ IK 中文分词器成熟<br>✅ Spring AI 官方 VectorStore 实现<br>✅ 国内生态成熟、社区活跃 | 内存占用较高（建议 4G+） | **选用** |
| Redis Stack | ✅ 缓存 + 向量二合一，组件少 | ❌ 向量检索功能不如 ES 成熟<br>❌ 中文分词需额外处理<br>❌ 不支持真正的 BM25 混合检索 | 不选 |
| Milvus | ✅ 专业向量数据库，性能极致 | ❌ 独立部署，运维成本高<br>❌ 单体应用过度设计 | 不选 |
| 阿里云 OpenSearch | ✅ 与阿里生态天然集成 | ❌ 绑定云平台，非自托管<br>❌ 需额外付费 | 备选（云部署时） |

> **结论**：选用 **Elasticsearch** 作为向量存储。理由是——它能在**一个组件内**同时完成向量语义检索（dense_vector）和 BM25 关键词检索，天然支持 RRF 混合检索融合，无需引入额外的检索引擎。IK 分词器对中文医疗文本的分词效果经过了长期验证。

### 2.4 RagService - 使用 Spring AI 实现 RAG

```java
@Service
public class RagService {

    private final ChatClient chatClient;            // DashScope 对话
    private final VectorStore vectorStore;           // Elasticsearch 向量存储
    private final HybridSearchService searchService; // 混合检索

    // Spring AI Alibaba 内置的 DashScopeEmbeddingModel
    // 向量化文本后存入 VectorStore
    public void indexDocument(Document doc) {
        vectorStore.add(List.of(doc));
    }

    // RAG 主流程：检索 -> 增强 -> 生成
    public ChatResponse generate(String query, List<Message> history) {

        // 1. 混合检索
        List<Document> retrievedDocs = searchService.hybridSearch(query, 5);

        // 2. 构建 Prompt（Spring AI PromptTemplate 或手动拼接）
        String context = buildContext(retrievedDocs);
        String systemPrompt = loadPromptTemplate("qa.st");

        // 3. 使用 Spring AI ChatClient 生成
        return chatClient.prompt()
                .system(s -> s.text(systemPrompt).param("context", context))
                .user(query)
                .advisors(new QuestionAnswerAdvisor(vectorStore))  // 也可用内置 Advisor
                .call()
                .chatResponse();
    }
}
```

**SSE 流式响应设计**（使用 Spring AI Alibaba 的 Flux 支持）：

```
GET /api/v1/chat/messages/stream?session_id=sess_abc&content=秋季如何预防感冒

响应 (text/event-stream):
data: {"type":"start","message_id":"msg_001"}

data: {"type":"content","chunk":"秋季预防感冒可以","evidence_level":4}

...

data: {"type":"end","sources":[...],"usage":{"total_tokens":350}}
```

ChatController 实现示意：

```java
@GetMapping("/chat/messages/stream")
public Flux<ServerSentEvent<String>> streamChat(
        @RequestParam String sessionId,
        @RequestParam String content) {

    return chatService.streamMessage(sessionId, content)
            .map(chunk -> ServerSentEvent.<String>builder()
                    .data(JsonUtils.toJson(chunk))
                    .event(chunk.getType())
                    .build());
}
```

## 六、与原设计的关键差异总结

| 维度 | 原设计 | 改进后 |
|------|--------|--------|
| 架构 | 多模块微服务 + Gateway | 单模块 Spring Boot 单体 |
| LLM 集成 | 手写 BailianClient | Spring AI Alibaba 自动配置 |
| 对话客户端 | 自定义 HTTP 客户端 | Spring AI `ChatClient` |
| 向量化 | 手写 EmbeddingService | `DashScopeEmbeddingModel` |
| Prompt 管理 | 手写 PromptTemplate | Spring AI Resource 模板 + PromptTemplate |
| 认证 | Gateway AuthFilter | Spring Security Filter |
| 缓存 | 必须 Redis | Caffeine 本地缓存，可选 Redis |
| 数据库表 | 16 张（含 system_log 独立表） | 12 张（合并冗余表） |
| 流式方案 | WebSocket + SSE 并存 | 统一 SSE（Spring AI Flux 支持） |
| 检索引擎 | 独立 search 模块 | 合并入 RAG 模块 |
| 证据分级 | 独立 evidence 模块 | 合并入 knowledge 模块 |
| LLM 服务 | 独立 llm 模块 | Spring AI Alibaba 自动装配 |
| 外部键设计 | session_id VARCHAR 做外键 | 统一用 BIGINT id 做主键/外键 |
